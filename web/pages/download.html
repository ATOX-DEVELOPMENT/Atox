Download Atox

macOS

Apple Silicon .dmg Intel Mac .dmg

Not sure which one? Open Apple menu → About This Mac: if the chip says Apple M…, take Apple Silicon.

Open the .dmg and drag Atox to your Applications folder.

Linux

AppImage x64 Arch Linux .pacman

The AppImage runs on any distribution and updates itself. The Arch package installs with pacman and updates the same way.

Make the AppImage executable and run it:

chmod +x Atox-*.AppImage
./Atox-*.AppImage

On first launch Atox adds itself to your app launcher. Keep the file where it is — for example in ~/Applications — so updates can replace it in place. On Arch Linux and Omarchy you can install the package instead: 

sudo pacman -U Atox-*.pacman

First launch

On a Mac, Atox isn't notarized by Apple yet, so the first time you open it macOS says it can't verify the developer. This happens only once:

  1. Open Atox and close the warning.
  2. Go to System Settings → Privacy & Security.
  3. Scroll down and click Open Anyway next to Atox.

Atox runs the agents you already have, so install and sign in to at least one of them first — Claude Code or Codex.

Projects and chats

A project is a folder on your computer. Click New project (⌘O) and pick a folder — Atox opens a first chat in it right away.

A chat is a conversation with an agent working in that folder. Create one with New chat (⌘N) and choose the agent. Chats are named after what the agent is doing; double-click a chat to give it your own name.

  • Drag projects and chats to reorder them.
  • Right-click a project to start a chat, open its pull requests and issues, rename it, change its icon and color, move it to another space, open it in Finder or your file manager, copy its path or remove it from the list. The folder itself stays on disk.
  • Right-click a chat to open it to the side, rename it, fork it, archive it or delete it. Archived chats keep their history: restore them in Settings → Archive.
  • Attach files with the paperclip, drop them into the chat or paste a screenshot — the agent gets them with your message.
  • Send the next message while the agent is still working: it waits in line. Press Esc to stop the agent.

Agents

Atox detects which agents are installed: Claude Code and Codex. A new chat starts with the agent you used last; switch the agent, model or effort from the picker under the message field at any moment. Type / to see the agent's commands.

Switching mid-chat keeps the conversation: the new agent gets everything said so far and carries on from there. A reply that is already in progress is finished by the agent that started it.

When an agent needs permission to run a command or asks a question, a card appears in the chat. Answer in one click, pick an option or type your own.

Fork a chat

Right-click a chat and choose Fork chat to try another approach without losing the first one. The fork starts with the whole conversation so far and goes its own way; it sits under the original chat.

Agent teams

Agents in Atox can delegate. Ask Claude to “have Codex review this” and it starts Codex in a new chat with the task. When Codex is done, its report arrives in Claude's chat as a new message, and Claude carries on.

Workers show up under the chat that started them as a collapsible “N agents” group. You can open any worker to watch it or step in. Ask the agent to remove workers you no longer need — for example, one it started by mistake. The Agents page (⇧⌘A) lists every running agent, with the ones that wait for you first.

Agents do this with the atox command, which is available in every Atox terminal. Claude Code and Codex learn it automatically; you can also use it yourself:

atox agentsList installed agents
atox models [agent]List the models and efforts of an agent
atox start <agent> "<task>"Start a worker with a task; add --model and --effort to choose them
atox workersList your workers and their state
atox send <chat-id> "<message>"Message a worker
atox remove <chat-id>Stop a worker and delete its chat
atox send parent "<question>"Worker: ask the agent that started it
atox report "<summary>"Worker: send the result back

A few rules keep teams cheap and predictable:

  • Up to 4 workers per chat can run at the same time.
  • Workers can't start workers of their own.
  • Each worker reports once per task, so it can't flood your chat.
  • Workers start without trust or permission prompts: Atox trusts the project folder for them and allows the atox command only.

Changes, terminal and repository

  • Changes (⇧⌘D) lists every file changed since the last commit, with its diff. Discard what you don't want.
  • Terminal (Ctrl `) is a real shell in the project folder in a panel next to the chat. It keeps running while hidden.
  • Repository (⇧⌘G) shows the project's pull requests and issues. It uses the GitHub account signed in to gh.

Board

The Board turns GitHub issues into tasks for agents. Pick the repositories to follow, then drag an issue from Backlog to Queue or In progress: choose the agent, model and effort, add a note if you like, and the agent works on it in its own git worktree, so your folder is not touched. Finished tasks wait in Review; Done keeps a task for a day. Search the board and filter it by organization, repository or assignee. How many agents work at once is set in Settings → GitHub, along with the accounts you can switch between.

Usage and limits

The usage button next to your name in the sidebar shows how much of your Claude and Codex plan limits you have used and when each resets. Settings → Usage adds token totals for today and for all time.

Spaces

Spaces group projects — for example work, side projects and clients. They sit as tabs above the project list: click one to switch, or press Ctrl+1–9. Each space remembers which project was open. Click + to add a space; right-click a tab to rename, recolor or delete it. Projects of a deleted space move to another one.

Side by side

⌘-click a chat (Ctrl-click on Linux), or right-click it and choose Open to the Side, to see two chats of the same project at once. Drag the divider to resize. The layout is saved with the project.

Chat status

  • Pulsing — the agent is working.
  • Orange — it waits for your answer.
  • Blue — it finished while you were elsewhere.
  • Gray — nothing new.

When a task takes longer than ten seconds and you're in another chat or app, Atox also sends a notification. Click it to jump to the chat. Turn on a soft chime in Settings → General if you like.

Settings

  • General — your name in the sidebar, updates, sounds, anonymous usage stats, appearance (light, dark or system theme and an accent color) and keyboard shortcuts.
  • Usage — plan limits and token totals.
  • Archive — archived chats, ready to restore.
  • GitHub — accounts and the agent limit for the board.
  • Plugins, Skills and MCP — what your agents have installed.

Updates

Atox checks for new versions on its own. When one is ready, an Update button appears at the bottom of the sidebar — click it and Atox restarts on the new version. Running agents are stopped by the restart, so finish what they're doing first. You can also check by hand in Settings → General.

The Linux AppImage updates the same way. If you installed the Arch package, download the new one and install it with sudo pacman -U.

FAQ

macOS says Atox can't be opened

See First launch — it's a one-time step.

The AppImage doesn't start

Check that the file is executable (chmod +x). AppImages need FUSE; on Arch and Omarchy install it with sudo pacman -S fuse2, or use the Arch package.

My agent isn't in the list

Atox looks for the agent's command in your shell. Make sure claude or codex works in your terminal, then restart Atox.

Does Atox see my code or send it anywhere?

No. Your agent talks to its own service exactly as it does in your terminal, and Atox has no accounts. The only thing it sends is anonymous usage statistics (app version and OS, no projects or chats), which you can turn off in Settings → General. See the privacy policy.

Where is my data?

In ~/Library/Application Support/Atox on a Mac and in ~/.config/Atox on Linux. Removing a project from Atox never touches the folder on disk.
